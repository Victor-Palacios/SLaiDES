## T-018 — advisory warnings + min-score gate — commit `12659b4`

- Nine `W_AESTH_*` codes (one per sub-metric): `W_AESTH_BALANCE`, `_WHITESPACE`,
  `_ALIGNMENT`, `_OVERLAP`, `_CONTRAST`, `_RICHNESS` (per-slide), `_HIERARCHY`,
  `_HARMONY` (theme-level, emitted once at the deck level), and `_CONSISTENCY`
  (deck-level). Each warning carries `{code, slide, metric, value, threshold,
  message, suggested_fix}` — the linter-issue shape, for tooling parity.
- `ADVISORY_THRESHOLDS` were tuned from the observed per-slide sub-score distribution
  across the 40-design example library, so a warning flags a genuine outlier rather
  than ordinary variation (e.g. the structurally-low alignment score of legitimate
  multi-column grids does **not** trip `W_AESTH_ALIGNMENT`). Documented as HEURISTIC
  in `docs/AESTHETICS.md`; calibration stays DEFERRED.
- Warnings are surfaced in both the human output and the `--json` report (new
  `warnings` key); the report is deterministic (two runs identical).
- `--min-score N` is an **opt-in** CI floor: exits 1 when the deck score is below N,
  exit 0 otherwise. Without the flag, `score` never gates.
- Added a `__main__` guard to `slidekit.cli` so `python -m slidekit.cli` works (used
  by the new CLI tests).
- 9 new tests (`tests/test_aesthetics/test_score.py` warnings cases +
  `tests/test_cli/test_score_cli.py` gate cases).

## Research (standing task) — commit `1af2b6f`

- **#16 Lok, Feiner & Ngai — Evaluation of visual balance for automated layout**
  (IUI '04, DOI 10.1145/964460.964462). Visual-balance metric from per-element visual
  weight (bounding-box area/position) → moment about the layout centre. Geometry-only.
- **#17 Bauerly & Liu — compositional elements on interface/design aesthetics**
  (IJHCS 64(8):670–682, 2006, DOI 10.1016/j.ijhcs.2006.01.002). Human-validated
  symmetry/balance models from element bounding boxes.
- **#18 Zhang & Xue — Visual Moment Equilibrium** (Symmetry 18(1):41, 2026,
  DOI 10.3390/sym18010041). Moment-equilibrium balance model targeting asymmetric
  layouts that simple centroid-distance scores mishandle.
- Integration direction **logged, not yet applied**: #16 + #18 both frame balance as a
  *moment about the layout centre*; slidekit's current `_balance` uses centroid distance
  (a special case). A future Phase 10 refinement could adopt the area-weighted moment
  formulation for off-centre compositions — deterministic, no render.
