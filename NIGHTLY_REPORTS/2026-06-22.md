Acted on the 2026-06-21 next-step: evaluate a **largest-empty-rectangle / "white-space
free-flow"** refinement to `_whitespace`, primary-source verified first.

- **Source check:** Harrington et al. (ref #10, DocEng 2004) lists "white-space
  free-flow" and O'Donovan et al. (ref #14) has a "white space" energy term, but
  **neither publishes a closed-form free-flow formula** (confirmed against the ACM
  abstract and the authors' patent US20070208996A1 — the free-flow computation is not
  disclosed). Any implementation would be HEURISTIC, not a faithful reproduction.
- **Redundancy finding:** the concern ("penalise one dominant empty region") is the
  *uneven-whitespace* case — content shoved to one side leaving a big void opposite —
  which `_balance` already scores (area-weighted moment about the centre axes, refs
  #4/#16/#17/#18). A centred sparse hero (big-number) has evenly-distributed
  whitespace and is correctly NOT penalised — a naive largest-empty-rectangle penalty
  would wrongly punish it and risk the designed-beats-plain invariant.
- **Decision:** do **not** add the metric (redundant + no published formula).
- **Honesty fix:** `docs/AESTHETICS.md` and `docs/RESEARCH_TRACE.md` claimed
  `_whitespace` already penalised distribution ("warns when largest empty > 3×
  median"). The code only ever scored a coverage band. **Corrected both docs** to
  match the code and cross-reference `_balance`; recorded the full evaluation in
  NOTES.md. **No code changed.** Logged as board **T-047** (research, done).
