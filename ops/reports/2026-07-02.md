### Commit `6b169e7` — web-gallery descender clipping (FB-010, FB-015, FB-016)
- **Root cause (vision-confirmed).** The feedback website renders each layout from
  `web/data/previews.json` fragments produced by `emit/html_preview._node_html`. Each text
  node got a border-box exactly one line tall, then the emitter stole 10px with
  `padding:5px` top+bottom and left `line-height` unset — the browser fell back to a
  font-dependent `normal` line-height (taller on the operator's phone, which lacks the named
  fonts) and `overflow:hidden` chopped the g/p/y descenders. **252 text nodes** across the
  gallery were affected.
- **Fix.** Pin `line-height` to `LINE_SPACING_SINGLE`, zero the vertical padding (a resolved
  `rect.h` already carries the vertical space), and set `.node-text{overflow:visible}` in both
  the site CSS and the debug emitter.
- **FB-010 (icon-text-rows "can't read the subtext") was a REAL geometry defect**, not just a
  preview artifact: the handler split each row as heading-line + 0.3″ gap + remainder, and the
  remainder body box came out **shorter than one line** (46.7px < 54.4px) so its single line
  clipped. Fixed by pairing heading+body on a 0.1″ inner gap (shared `group_id`, E_GAP-exempt,
  matching feature-list) and flooring `body_h` at one line. Goldens 03/10 regenerated.
- **Codified:** `tests/test_web/test_web_previews.py::test_text_nodes_pin_line_height_and_never_clip_descenders`
  (line-height pinned + no vertical padding + one line box fits each node height).
