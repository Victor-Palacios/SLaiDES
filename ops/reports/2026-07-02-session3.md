### Commit `76195b3` — retire the `two-column` component; reparent its family (FB-009 / T-055)
**Operator ask:** "delete this slide layout — redundant with comparison-columns."

**Inspection finding (surfaced, not silently accepted):** `two-column` was actually the
*general-purpose anchor* of the two-column family (free content slots, arbitrary column
weights), and `comparison-columns`, `image-half-bleed`, `chart-with-insight` all specialise
*from* it — so "redundant → delete two-column" inverts the base/specialisation relationship.
BUT the operator's read is content-accurate: the two-column specimen was literally titled
"Strengths vs Weaknesses" (a comparison) and reads as a duplicate of comparison-columns in the
gallery. Operator feedback needs no approval, so it was honored — via a reparent that keeps the
taxonomy coherent.

**What changed (end-to-end deletion + reparent):**
- **IR:** removed `TwoColumnSlide` model + its entry in the `Slide` union.
- **Layout:** removed `_layout_two_column` + its dispatch branch (shared helpers
  `_layout_content_list`/`ContentSlot` kept — still used by image-half-bleed).
- **Registry:** removed the `two-column` entry; promoted `comparison-columns` to family
  **anchor**; `image-half-bleed`/`chart-with-insight` now `variant_of: comparison-columns`.
  The family *name* stays "two-column" (the two-side-by-side skeleton is unchanged), so the
  registry invariants (one anchor per family, every variant → its anchor) still hold.
- **Scaffold:** `standard`/`pitch` starter templates now use `bullet-list` instead of
  two-column (still lint-clean out of the box).
- **Recommender:** the bare two-group fallback now suggests `comparison-columns`.
- **Examples:** deleted specimen `02_two_column.yaml` (+ its PDF + golden). Showcases
  converted, reusing existing components and preserving text: `10_all_components` dropped its
  two-column demo slide (it demoed the removed component and carried an icon slot);
  `demo-5` + `agents-in-ai` → `bullet-list` (both already had a comparison-columns slide, so
  no duplicate); `09_full_deck` → `comparison-columns` (no comparison present; adds variety).

**Deterministic verification / codified defect:** when `09_full_deck` first converted to
comparison-columns, `slidekit build` was lint-clean but the **verify harness** (the sanctioned
LibreOffice render) FAILED — 3.96% ink outside computed rects on the comparison slide, because
long items wrapped past their one-line boxes. Items were shortened to single lines and the
harness now passes. The harness *is* the deterministic gate for this class (ink-outside-rects
on real render) — it caught the defect without a manual eyeball, so no new check was needed.

**Feedback-store side effect:** `slidekit.feedback.store` validates each comment's `component`
against the live catalog, so `FB-009 component: two-column` would fail validation once the
component was gone. Retargeted FB-009's component to `comparison-columns` (the surviving family
member that absorbed its role), original intent preserved in the comment + notes. A generic
"retired-component" allowance in the schema would be scope creep and was NOT added.
