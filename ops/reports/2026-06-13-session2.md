## Phase 6 — Verification harness (CI only) — COMPLETE

Commits: `7632299`, `518f8d0`, `9ffc3cd`

**Render-drift harness** (`src/slidekit/verify/`): builds a deck, renders it
`pptx → pdf (soffice --headless) → png (pdftoppm)`, and runs two cheap, deterministic
pixel heuristics against the `ResolvedDeck` geometry — no LLM, no human:

1. `ink_outside_rects` — every ink pixel (differs from the slide surface colour)
   must fall inside the slack-dilated union of resolved node rects. Core drift signal.
2. `ink_in_margin` — no ink in the 0.5" edge band except the page-number chrome corner.

Pillow-only (no numpy); all per-pixel work is C-level `ImageChops`/`ImageDraw`, so a
2000×1125 slide checks in milliseconds. Scale is derived from the actual rendered
image size, so any DPI/page rounding self-corrects. Thresholds (stray ink ≤1% of ink,
margin ink ≤0.1% of slide) are tuned so clean decks pass with headroom.

**Real defect surfaced and fixed.** The harness flagged ~1.1–1.7% stray ink on every
icon-bearing deck (03, 08, 09). Root cause: the Phase 5 emitter drew icons as an
unmeasured `[name]` text label, centred with word-wrap off, which LibreOffice
overflowed past the slot symmetrically. Per PLAN.md's rule that harness/linter
disagreements are fixed in emit/layout (never a per-deck visual loop), the emitter now
draws a **colored circle inscribed in the slot** — which is exactly what the Phase 2
spec specified for icons ("rendered into a colored circle"). Round-trip tests are
unaffected (they inspect text-box shapes only). After the fix, worst stray ink across
all 11 decks is 0.41% (vs the 1% threshold).

**CLI:** `slidekit verify <deck.yaml>…` (CI-only) prints a JSON report per deck, exit 1
on drift, exit 2 if render tools are missing.

**Tests** (`tests/test_verify/`, 15): all 11 decks (10 examples + demo-5) pass the
heuristics; a **sensitivity test** renders a real deck then checks it against
artificially shrunk geometry and asserts the harness *fails* — proving the heuristic
discriminates rather than trivially passing. Render-dependent tests skip cleanly when
`soffice`/`pdftoppm` are absent.

**CI wiring caveat (documented blocker, not a failure).** The workflow
(`ci/verify.yml`, triggers on layout/metrics/emit/verify/examples paths) is authored
and validated but **could not be pushed into `.github/workflows/`**: the unattended
nightly bot authenticates as a GitHub App whose token lacks the `workflows`
permission, so any push touching `.github/workflows/` is remote-rejected. The workflow
is therefore committed to `ci/verify.yml` with one-time install instructions in
`ci/README.md` (see also NOTES.md). The harness, CLI, and tests are fully functional
locally and in any CI that installs the file.
